## 0. Коммерческая модель: решения (обновлено 2026-11-22)

Этот раздел главнее разделов ниже там, где они расходятся (например, раздел 3 писался, когда аккаунт был необязательным и подписки не было).

### CONFIRMED — решения приняты владельцем

- **Тарифы.** Free и Pro.
  - Free: базовое управление компьютером; Remote Touchpad и Keyboard; просмотр экрана; ограниченная передача файлов; базовый мониторинг.
  - Pro (всё из Free, плюс): расширенные передача файлов и управление; RGB Sync; Automation Studio; расширенный мониторинг; другие продвинутые функции в будущем.
  - Оплата Pro — Monthly и Yearly. Цены не утверждены.
- **Аккаунты обязательны для всех**, включая Free: регистрация и вход; восстановление доступа; привязка устройств к аккаунту; проверка подписки и прав; управление подпиской; синхронизация статуса Pro между Windows и iPhone.
- **Сервер — единственный источник истины по правам (entitlements).** Локальный флаг `isPro` или проверка подписки только на клиенте недопустимы. Pro-команды отклоняет сам агент на ПК, а не интерфейс.
- **Аккаунт не даёт доступа к ПК.** Доступ к ПК — только QR-сопряжение и ключ устройства (ARCHITECTURE D4, D13).
- **Права Pro — по аккаунту владельца ПК** (а не того, кто подключился).
- **Free работает без сервера и без интернета.** Агент не проверяет привязку к аккаунту для Free-команд; аккаунт обязателен при первой настройке трея и iPhone.
- **Офлайн-льгота Pro:** токен прав действует 24 часа, плюс 7 дней льготы без связи с сервером. При возврате или отзыве (refund/revoke) льгота не применяется, если агент на связи.
- **Токен прав получает служба на ПК** исходящим HTTPS-запросом к серверу; телефон токены на ПК не передаёт. Вход в аккаунт на ПК — через трей одноразовым кодом с подтверждением на сайте или iPhone, без ввода пароля в трей.
- **Протокол v1 расширяется только аддитивно:** поля плана в `system.hello` (только после входа), команда `account.refresh`, коды `plan.required` и `plan.limit`, маркер `entitlements.v1` в `capabilities`.
- **Вход:** email и пароль с подтверждением email, плюс Sign in with Apple; 2FA (TOTP) — по желанию пользователя.
- **Удаление аккаунта** — внутри iOS-приложения (Guideline 5.1.1(v)), на сайте и в трее.
- **Платежи (требования):** оплата через сайт; Apple In-App Purchase там, где этого требуют актуальные правила Apple; проверка платежей на сервере; webhooks провайдеров; продление, отмена, возвраты; синхронизация между платформами. Данные банковских карт на своём сервере не хранятся.
- **Рынок — международный.** Россия не является основным рынком запуска.
- **Хостинг и данные (вариант C, текущий этап):** одна инфраструктура за пределами РФ; отдельного российского backend нет; двухрегиональная архитектура сейчас не внедряется; персональные данные пользователей из РФ не собираются до отдельной юридической проверки требований локализации (152-ФЗ).
- **Российские платёжные провайдеры** пока не подключаются; российское ИП или ООО ради Nexus PC сейчас не регистрируется.
- **Сайт** — на английском и русском; в будущем — регистрация, тарифы, управление аккаунтом и оплата там, где это допустимо.
- **Бюджет:** правило «нулевой бюджет» (ARCHITECTURE D11) пересмотрено.
- **Автоматизации после окончания Pro** останавливаются, но не удаляются.
- **Обход Pro патчем агента** принимается как бизнес-риск; DRM не строим.
- **Безопасность прав (по аудиту security-auditor, 2026-11-22):** ключ ПК (proof-of-possession, по возможности TPM) и ротация refresh-токенов против клонирования; подпись токена — ECDSA P-256; в агенте закреплены 1 рабочий и 2 запасных открытых ключа сервера (приватные запасные — офлайн у владельца, без платного KMS); HTTPS службы — адрес-константа, закрепление ключей 2–3 промежуточных CA с запасными пинами. Подробно — `SECURITY.md`, «Аккаунты и права».
- **Новые исполнители:** `backend-developer` (зона `backend/**`) и `web-developer` (зона `site/**`) — нужно оформить в `.claude/agents` и `.claude/AGENT_RULES.md`.
- **Backend (2026-11-23):** Supabase Free, регион ЕС (Франкфурт), письма через бесплатную SMTP (Brevo или Resend); webhooks — в Edge Functions. Формат токена нейтральный, чтобы можно было перейти на свой .NET-сервис. Облачный проект создаёт владелец; до этого — локальная разработка и тесты. Рабочее `iss` — `https://api.<домен>` после выбора домена; до этого в агенте остаётся заглушка.
- **Сервер прав, E3 (2026-11-23):** новый одобренный вход ПК перепривязывает ПК к одобрившему аккаунту и отзывает старые refresh-токены — **уточнено по аудиту E3-5:** только если запрос подписан старым ключом ПК, либо после того, как текущий владелец удалил ПК или подтвердил перепривязку; первая привязка — по первому использованию; завершение входа подписывается новым ключом ПК; ответ сервера «права отозваны» не подписан (доверие через закреплённый HTTPS; вопрос — к аудиту security-auditor); аккаунтам без Pro выдаётся токен `plan:"free"`; refresh-токен ПК — 90 дней скользящий, лимиты частоты — по плану E3; платёжные записи после удаления аккаунта пока не удаляются (решение — к E7).
- **Вход ПК, E3-5 (2026-11-23):** при 20 ПК у аккаунта consume отвечает `pcs.limit`, код не тратится до конца срока; опрос consume — не больше 150 раз на код (10 мин × 5 с), дальше `code.invalid`.
- **Безопасность входа ПК (аудит E3-5, 2026-11-23):** одобрение в два шага (сначала имя ПК и время запроса, затем подтверждение), срок кода 5 минут, трей показывает аккаунт привязки — обязательно до публичного запуска; хэши кодов — HMAC-SHA-256 с секретом в секретах Supabase, не в БД.
- **Refresh ПК, E3-6 (2026-11-23, по рекомендации аудита):** отдельный секрет `REFRESH_HASH_PEPPER`; повтор после потерянного ответа — идемпотентный (тот же старый токен в течение ~60 с после `ok` получает тот же новый токен, обнаружение повтора не ослабляется); абсолютный предел жизни семьи сейчас не вводится; при неверном ключе ответ `revoked` одинаков для привязанного и отвязанного ПК; проверка Pro — в Edge по владельцу ПК при каждой выдаче токена прав.
- **Edge E3-7 (2026-11-23, по рекомендации архитектора):** миграция `entitlement_for_user` — Pro по владельцу ПК, которого вернула ротация; `sub` токена — **уточнено по аудиту E3-7:** HMAC с секретом `ENT_SUB_KEY` от user_id и pcId (ПК одного аккаунта по `sub` не связываются); `pending` — HTTP 202.
- **Аудит E3-7 (2026-11-23, по рекомендации):** IP клиента — из заголовка, который ставит платформа (`cf-connecting-ip`, иначе последний элемент XFF), проверить на стенде до продакшена; лимиты по IP — вспомогательные; общий предохранитель start считается после проверки подписи; секреты — base64 от ≥32 случайных байт; в `apikey` пользовательских вызовов — публичный anon-ключ, а не service_role.
- **Удаление аккаунта, аудит E3-8 (2026-11-23, по рекомендации):** свежесть входа — по сессии (`amr[].timestamp`) плюс `last_sign_in_at`; при удалении аккаунта с платной подпиской (E7) — отмена у провайдера до purge, для App Store — ссылка на управление подписками Apple и предупреждение; `payment_events` — только то, что требует закон, без email и user_id, срок — в политике конфиденциальности.

- **N2 — защита первой привязки ПК (CONFIRMED 2026-11-24):** `pcId` выводится из постоянного ключа устройства ПК, сервер сверяет `pcId` с ключом при первой привязке. Формат QR не меняется; реализация — в E4 (план `.claude/handoff/E4-PLAN.md`). Решения 2026-11-24: (1А) спаренные iPhone после обновления сопрягаются заново, совместимость со старым `pcId` не делается; (2) без TPM — программный ключ CNG (неэкспортируемый, MachineKey, ACL только LocalSystem), при наличии TPM — ключ в TPM; (3) потеря ключа = новый ПК с новым `pcId`, старая запись занимает место в лимите 20 ПК до удаления владельцем.

## 2. Главные ограничения, которые меняют план

1. **App Store невозможен без Apple Developer Program** (≈ $99/год). Это противоречит решению D11 «нулевой бюджет». Без него можно подготовить всё, кроме самой публикации, TestFlight, APNs, App Groups и multicast-entitlement.
2. **Guideline 4.2.7 (Remote Desktop Clients):** приложение может подключаться только к ПК пользователя **в локальной сети**. Режим «вне дома через Tailscale» в сборке для App Store рискован → предлагаю выключить его в App Store-сборке (код остаётся).
3. **Guideline 2.3.1 — скрытые функции запрещены.** Поэтому «Developer Mode» нельзя прятать жестом в релизной сборке. Решение: инструменты разработчика компилируются только в Debug/внутренних сборках (`#if DEBUG`); в релизе — открытый и описанный раздел «Диагностика» (экспорт журнала без секретов).
4. **Guideline 2.1 — рецензент Apple не имеет вашего ПК.** Нужен честно подписанный **демо-режим** («Демо-ПК», симулятор агента в NexusKit) и видео для App Review. Это не «функция ради количества», а условие прохождения проверки.
5. **Guideline 5.1.1(v):** раз есть регистрация — обязательно удаление аккаунта внутри приложения. Вход только email+пароль → «Sign in with Apple» (4.8) не обязателен.
6. **Лицензии:** OpenRGB и PawnIO — GPL-2.0. Распространять их в установщике можно без изменений, но нужно приложить лицензию (есть) **и предложение исходного кода/ссылку** на точную версию — добавлю в установщик и документацию.
7. **Нет Mac.** Подпись и загрузка в App Store Connect возможны из GitHub Actions (сертификат и ключ App Store Connect API — в GitHub Secrets). Никаких секретов в репозитории.

## 3. Аккаунты: сравнение backend-ов

Что аккаунт **даёт** в Nexus PC (честно): список ваших ПК на всех ваших телефонах и после переустановки, профиль, основа для будущего Android и (когда-нибудь) push/relay. Что аккаунт **не даёт**: доступ к ПК. Доступ к ПК — только локальное сопряжение по QR.

| Критерий | **Supabase Free** | Firebase Auth (Spark) | AWS Cognito (Lite) | Свой сервер (ASP.NET Core) |
|---|---|---|---|---|
| Старт | $0 | $0 | $0 | VPS ≈ $4–6/мес |
| Бесплатно | 50k MAU, 500 МБ БД; **проект засыпает после 7 дней без активности**; без бэкапов | ~50k MAU; есть дневные лимиты Identity Platform на Spark | 10k MAU | — |
| Письма | Своя SMTP обязательна (встроенная — 2 письма/ч и только участникам); бесплатно через Brevo/Resend | Встроенные шаблоны, отправитель `@firebaseapp.com` | Встроенно ~50/день, дальше SES | Сам |
| Подтверждение email / сброс пароля | Да (ссылка **или 6-значный код**) | Да (ссылка) | Да (код) | Писать самим |
| Удаление аккаунта | Серверная функция (Edge Function, бесплатно) | Из клиента (`user.delete`) | Из клиента | Сам |
| Список сессий и отзыв по одной | Да (выход «на других устройствах», сессии в `auth.sessions` через серверную функцию) | Только «выйти везде», и то через Admin SDK (нужен Blaze) | Глобальный выход | Сам |
| Короткие токены + обновление | JWT ~1 ч (настраивается), ротация refresh с обнаружением повтора | ID-token 1 ч + refresh | 5 мин–1 сутки + refresh | Сам |
| Защита от перебора | Встроенные лимиты + CAPTCHA (hCaptcha/Turnstile бесплатно) | Встроенная | Встроенная | Сам |
| iOS / Android | `supabase-swift` (MIT), `supabase-kt` | Официальные SDK | Amplify | любые |
| Привязка к поставщику | Низкая: open source, Postgres, можно перенести/self-host | Высокая (Google) | Высокая (AWS) | Нет |
| Риск безопасности | Низкий (готовый сервис + RLS) | Низкий | Низкий | **Высокий** (своя криптография сессий) |

### Рекомендация: **Supabase Free** + бесплатная SMTP (Brevo или Resend) — CONFIRMED 2026-11-23 (см. раздел 0)
- Единственный бесплатный вариант, где есть всё из ТЗ, включая **управление сессиями**.
- Подтверждение и сброс через **6-значный код в письме**, а не ссылку: не нужен домен для Universal Links, одинаково для iOS и Android, ссылку нельзя перехватить чужим приложением.
- «Засыпание» после 7 дней касается только неактивного проекта (во время разработки); с живыми пользователями не происходит. Если продукт вырастет — Pro $25/мес (только с вашего согласия).
- В приложении будет только публичный `anon`-ключ (он и задуман публичным; права ограничивает RLS). `service_role` живёт только в Edge Function.
- Запасной вариант — Firebase (проще письма, но нет списка сессий и сильная привязка к Google).

### Архитектура аккаунтов

```
iPhone/Android ──(HTTPS, токены)──► Supabase Auth + Postgres (RLS)
     │                                таблица my_pcs: user_id, display_name,
     │                                platform, added_at, last_seen_at
     │                                (без IP, MAC, отпечатков, ключей)
     │
     └──(LAN, WSS + pinning + ключ Secure Enclave)──► Nexus.Agent на ПК
                                       (устарело: см. раздел 0)      
```

Правила:
- **Две независимые системы.** Аккаунт хранит только «визитку» ПК. Даже полный взлом аккаунта не даёт команд ПК: нет ключа сопряжения, нет отпечатка, нет адреса.
- **[УСТАРЕЛО — см. раздел 0: агент получает токен прав по HTTPS]** **Агент не меняется и не ходит в интернет.** Локальное управление без регистрации и без интернета работает как сейчас (это будет тестом).
- «Статус подключения» в «Мои устройства» вычисляет **телефон** локально; на сервер уходит только «когда последний раз видел».
- «Удалить ПК из аккаунта» удаляет запись; приложение отдельно предлагает «Также отключить этот iPhone от ПК» (локальный отзыв своего устройства, если ПК в сети).
- На новом телефоне ПК из аккаунта показывается как «нужно подключить заново» → QR.
- Refresh-токен — в Keychain (`AfterFirstUnlockThisDeviceOnly`), access-токен — только в памяти.
- Удаление аккаунта: повторный ввод пароля → Edge Function удаляет записи и пользователя → локальный выход. Сопряжения с ПК остаются (это локальное доверие), пользователь об этом предупреждён.
- Бизнес-логика — в новом модуле `NexusKit/Account` (протокол `AccountBackend`, реализация Supabase за ним; тесты на подставном HTTP). SwiftUI только показывает.

## 8. Аудит безопасности — предварительные находки

| # | Где | Находка | Предложение |
|---|-----|---------|-------------|
| S1 | Аккаунт ↔ ПК | Риск смешать системы | Строгое разделение (раздел 3) + тест: токен аккаунта не принимается агентом, запись ПК из аккаунта не даёт подключения |
| S2 | Supabase | Доступ к чужим записям | RLS `user_id = auth.uid()` на всех таблицах, тесты RLS (два пользователя) |
| S3 | Установщик | Без подписи, обновление = артефакт Actions | GitHub Releases + манифест с SHA-256, подписанный Ed25519 (ключ — секрет CI), проверка в установщике и в «Проверить обновления»; Authenticode — когда будет сертификат |
| S4 | Канал служба↔трей | Проверка по пути, не подписи | Оставить путь (Program Files пишет только админ), добавить Authenticode-проверку при подписанных сборках |
| S5 | Служба | LocalSystem | Документировано; переход на `NT SERVICE\NexusPCAgent` — отдельная задача (затрагивает сертификат, OpenRGB/SMBus) |
| S6 | GitHub Actions | Действия по тегу | Закрепить SHA, Dependabot для actions/NuGet, минимальные `permissions` (уже `contents: read`) |
| S7 | `nexuspc://` | Любой сайт может запустить профиль/блокировку | Для публичного продукта — подтверждение перед выполнением, если приложение открыто ссылкой извне |
| S8 | Tailscale-диапазон 100.64/10 | Это ещё и CGNAT провайдеров | **Решено:** диапазон убран из агента |
| S9 | Сообщения об ошибках | Учат запускать PowerShell от администратора | Заменить на путь в окне трея |
| S10 | GPL-компоненты | Нет предложения исходников | Добавить ссылку на исходники точных версий |
| S11 | DevClient | Ключ без шифрования | Не входит в установщик (проверено: payload — только Agent/Tray/OpenRGB/PawnIO); оставить |

Полный аудит по списку ТЗ (authn/authz, pairing, TLS, файлы, тачпад, клавиатура, экран, буфер, служба, каналы, установщик, обновления, зависимости, CI, секреты) — в `docs/SECURITY.md` на этапе C.

### Риски
- Редизайн затрагивает все экраны iOS, а собрать и запустить их можно только в CI (нет Mac) → небольшие шаги, сборка IPA на каждом шаге, ручная проверка на вашем iPhone.
- Новая зависимость `supabase-swift` (MIT) — по D10 требует вашего одобрения. Альтернатива — тонкий клиент к REST API Supabase на `URLSession` без SDK (меньше кода чужих, проще аудит). Рекомендую **без SDK**.
- Переход на платный аккаунт Apple меняет bundle ID и подпись; bundle ID после публикации поменять нельзя.
