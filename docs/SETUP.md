# Nexus PC — Установка на Windows

## Установка одним файлом (P11, рекомендуется)

Нужны Windows 10 22H2+ или Windows 11 (64-бит). Всё остальное — внутри установщика: .NET 10, OpenRGB 1.1 и драйвер PawnIO (с 2026-11-18). Ручная установка ниже (для разработки) по-прежнему требует .NET SDK 10.

1. Откройте https://github.com/Narek814/nexus-pc/actions/workflows/ci.yml → последний запуск с зелёной галочкой → внизу **Artifacts** → **NexusPC-Setup** (скачается zip, внутри `NexusPC-Setup.exe`).
2. Запустите `NexusPC-Setup.exe`. Windows спросит права администратора — «Да».
   Файл не подписан (подпись стоит денег), поэтому SmartScreen может показать «Windows защитила ваш компьютер» → **Подробнее** → **Выполнить в любом случае**.
3. Установщик сам: останавливает старую версию, копирует программы в `C:\Program Files\NexusPC`, создаёт или обновляет службу (автозапуск, перезапуск при сбое), правило брандмауэра «только частная сеть», запускает службу и трей, включает автозапуск трея. Если домашняя сеть отмечена как общественная, спросит, сделать ли её частной.
4. Первый раз: значок «N» у часов → **Подключить iPhone…**

**Обновление** — скачать новый `NexusPC-Setup.exe` и запустить. Сопряжения, разрешения, автоматизации, профили и история сохраняются.

**Разрешения телефона** (тачпад, файлы, буфер обмена, автоматизации) — значок «N» → **Устройства и разрешения…** → отметить → «Сохранить разрешения» (Windows спросит права администратора). Там же — «Отключить устройство».

**Удаление**: `NexusPC-Setup.exe --uninstall` (данные и сопряжения остаются) или `NexusPC-Setup.exe --purge` (всё, включая сертификат; резервные копии папки данных `NexusPC.backup-…` не удаляются — установщик выводит их список, удалите вручную, если не нужны). Журнал установщика: `%TEMP%\NexusPC-Setup.log`.

Wake-on-LAN (включение ПК с телефона) установщик не настраивает — это настройки сетевой карты и BIOS, см. docs/REMOTE.md.

## Ручная установка из исходников (для разработки)

> Установщик выше делает то же самое. Эти шаги нужны, только если вы собираете Nexus PC сами.

## 1. Инструменты (один раз)

Откройте **PowerShell от имени администратора** (Пуск → PowerShell → правой кнопкой → «Запуск от имени администратора»):

```powershell
winget install Microsoft.DotNet.SDK.10
```

```powershell
winget install Git.Git
```

Закройте и снова откройте PowerShell от имени администратора, чтобы команды `dotnet` и `git` стали доступны.

## 2. Код

```powershell
cd $env:USERPROFILE
```

```powershell
git clone https://github.com/Narek814/nexus-pc.git
```

Если репозиторий приватный, Git попросит войти в GitHub в браузере.

Проверка, что всё собирается и тесты проходят на вашем ПК:

```powershell
dotnet test nexus-pc\windows\Nexus.slnx
```

## 3. Сборка агента

```powershell
dotnet publish nexus-pc\windows\Nexus.Agent -c Release -o "C:\Program Files\NexusPC\Agent"
```

## 4. Служба Windows

Проверка, что сборка на месте (должно быть `True`):

```powershell
Test-Path "C:\Program Files\NexusPC\Agent\Nexus.Agent.exe"
```

Создание службы. Используется `New-Service`, а не `sc.exe create`: в PowerShell кавычки внутри аргументов `sc.exe` искажаются, и путь с пробелом ломается (ошибка 1060 на следующих шагах).

```powershell
New-Service -Name NexusPCAgent -BinaryPathName '"C:\Program Files\NexusPC\Agent\Nexus.Agent.exe"' -DisplayName "Nexus PC Agent" -StartupType Automatic
```

Перезапуск при сбое:

```powershell
sc.exe failure NexusPCAgent reset= 86400 actions= restart/5000/restart/5000/restart/60000
```

```powershell
sc.exe start NexusPCAgent
```

```powershell
sc.exe query NexusPCAgent
```

Ожидается `STATE : 4 RUNNING`. Служба работает от `LocalSystem` (см. SECURITY.md §4). Данные: `C:\ProgramData\NexusPC` (доступ только у SYSTEM и администраторов). Сертификат: хранилище «Локальный компьютер → Личное», имя `Nexus PC Agent <pcId>`.

## 5. Брандмауэр — только частная сеть

```powershell
New-NetFirewallRule -DisplayName "Nexus PC Agent" -Direction Inbound -Program "C:\Program Files\NexusPC\Agent\Nexus.Agent.exe" -Protocol TCP -LocalPort 47800 -Profile Private -Action Allow
```

Проверьте, что домашняя сеть отмечена как **частная** — иначе iPhone получит «ПК не ответил вовремя» (так было на реальном ПК: Windows отметила домашний Wi-Fi как Public):

```powershell
Get-NetConnectionProfile
```

Если у вашей сети `NetworkCategory : Public`, сделайте её частной (окно администратора; `9` — ваш `InterfaceIndex` из вывода выше):

```powershell
Set-NetConnectionProfile -InterfaceIndex 9 -NetworkCategory Private
```

В общественных сетях (кафе и т. п.) оставляйте Public — там агент недоступен.

Порт в роутере **не открывайте**. Для доступа из интернета — Tailscale (этап P2/P11).

## 6. Проверка с тестовым клиентом

Окно 1 — PowerShell **от имени администратора**:

```powershell
& "C:\Program Files\NexusPC\Agent\Nexus.Agent.exe" pair
```

Появятся код и ссылка `nexuspc://pair?...`. Не закрывайте окно.

Окно 2 — обычный PowerShell (подставьте ссылку из окна 1 в кавычках):

```powershell
dotnet run --project $env:USERPROFILE\nexus-pc\windows\Nexus.DevClient -- pair "nexuspc://pair?..." --host 127.0.0.1
```

В обоих окнах появится одинаковый 6-значный код проверки. Если совпадает — в окне 1 нажмите `y` и Enter.

Дальше в окне 2:

```powershell
dotnet run --project $env:USERPROFILE\nexus-pc\windows\Nexus.DevClient -- send pc.status --host 127.0.0.1
```

Выключение через 10 минут (Windows покажет уведомление), затем отмена:

```powershell
dotnet run --project $env:USERPROFILE\nexus-pc\windows\Nexus.DevClient -- send power.shutdown --delay 600 --confirm --host 127.0.0.1
```

```powershell
dotnet run --project $env:USERPROFILE\nexus-pc\windows\Nexus.DevClient -- send power.cancel --host 127.0.0.1
```

Список устройств и отзыв (окно администратора):

```powershell
& "C:\Program Files\NexusPC\Agent\Nexus.Agent.exe" devices
```

```powershell
& "C:\Program Files\NexusPC\Agent\Nexus.Agent.exe" devices revoke <deviceId>
```

У каждого устройства в списке `devices` есть поле `fingerprint`: это отпечаток ключа устройства из 16 шестнадцатеричных символов, например `3FA2C91B07D4E658`. При вводе регистр букв не важен, и можно разделять группы пробелами, двоеточиями или дефисами.

**Что происходит при отзыве.** С момента, когда вы нажали «Отключить устройство» (или выполнили `devices revoke`), автоматизации этого устройства больше не запускаются: ни вручную, ни по расписанию, датчику, включению ПК или входу в Windows. Такие пропуски попадают в историю ПК с пояснением «Пропущена: устройство отзывается». Уже идущие автоматизации устройства останавливаются. Если одна из них в этот момент выполняет шаг (например, блокирует экран), отзыв дожидается конца этого шага, а следующие шаги уже не выполняются. Кроме того, отзыв ждёт шаги автоматизаций других устройств, которые к этому моменту уже стоят в очереди на выполнение; каждый такой шаг длится не дольше 15 секунд. Автоматизации других устройств продолжают работать.

Если у отзываемого устройства есть автоматизации с выключением или перезагрузкой ПК, окно «Устройства и разрешения» покажет предупреждение, а ответ `devices revoke` будет содержать поле `warning`: «У этого устройства есть автоматизации с выключением или перезагрузкой. Если одна из них уже запланировала выключение, отзыв его не отменяет». Предупреждение появляется, даже если эти автоматизации ни разу не запускались: оно не означает, что выключение действительно запланировано. Запланированное выключение Windows показывает уведомлением с отсчётом; отменить его можно с другого сопряжённого iPhone (кнопка отмены выключения) или командой `power.cancel` выше.

**Автоматизации отозванного устройства.** Автоматизацию видит, меняет и запускает только устройство, которое её создало. Если это устройство отозвано, его автоматизации не удаляются, но и не выполняются: по расписанию, по датчику, при включении ПК и при входе в Windows они пропускаются, а в истории ПК появляется запись «Автоматизация «…»: пропущена». В число 32 допустимых автоматизаций они не входят. Чтобы вернуть такой автоматизации владельца, выполните две команды в окне администратора.

Список автоматизаций без владельца, с их `automationId` и разрешениями, которые им нужны:

```powershell
& "C:\Program Files\NexusPC\Agent\Nexus.Agent.exe" automations owners
```

Передать автоматизацию сопряжённому устройству. `deviceId` возьмите из списка `devices`. Отпечаток **не копируйте** из вывода `devices`: перепишите его с экрана iPhone, которому передаёте автоматизацию. Он показан на главном экране приложения в строке «Отпечаток ключа этого iPhone», группами по 4 символа. Совпадение отпечатка — это и есть проверка, что выбран именно этот телефон. Если отпечаток вводится с пробелами, возьмите его в кавычки. Без кавычек каждая группа станет отдельным аргументом, и команда вместо передачи покажет справку.

```powershell
& "C:\Program Files\NexusPC\Agent\Nexus.Agent.exe" automations assign <automationId> <deviceId> "3FA2 C91B 07D4 E658"
```

Автоматизация передаётся, только если выполнены все условия:
- у неё нет владельца;
- устройство сопряжено именно с этим ПК, и его ключ в порядке;
- отпечаток совпадает с ключом устройства;
- у устройства есть все разрешения, которые нужны автоматизации;
- после передачи автоматизаций с владельцем будет не больше 32.

Если хоть одна проверка не прошла, команда сообщает причину, а автоматизация остаётся без изменений. Каждая попытка, удачная или нет, записывается в `audit.log` с типом `automations.assign`, id устройства, `automationId`, прежним владельцем (`formerOwner`) и результатом (`ok`, при ошибке — её причина). Сбой записи файла автоматизаций тоже попадает в журнал как неудача. После удачной передачи в истории ПК появляется запись «назначен владелец».

## 7. Nexus.Tray — приложение в трее (P1c)

Трей работает от вашего имени (не от администратора): запускает программы, блокирует экран, показывает QR-код для сопряжения. Служба и трей проверяют друг друга по пути установки, поэтому пути ниже менять нельзя.

Сборка (окно администратора):

```powershell
dotnet publish $env:USERPROFILE\nexus-pc\windows\Nexus.Tray -c Release -o "C:\Program Files\NexusPC\Tray"
```

Запуск **без** прав администратора (через Проводник — так он стартует с обычными правами, даже из окна администратора):

```powershell
explorer.exe "C:\Program Files\NexusPC\Tray\Nexus.Tray.exe"
```

Справа внизу, у часов, появится круглый значок «N» (возможно, под стрелкой «^»). Цветной — служба подключена, серый — нет связи.

Правой кнопкой по значку:
- **Запускать при входе в Windows** — включите, чтобы не запускать вручную.
- **Приложения и профили…** — добавьте программы (из меню «Пуск» или `.exe`), затем профили. Кнопка «Создать стандартные» добавит Gaming, Developer, Creator, Night — отметьте в каждом нужные программы и нажмите «Сохранить».
- **Подключить iPhone…** — QR-код и кнопка «Копировать ссылку». Пока iPhone-приложения нет, ссылку используйте с DevClient (как в шаге 6); подтверждение с кодом проверки появится в этом окне.

Проверка с DevClient (обычный PowerShell, после сопряжения):

```powershell
$nx = "$env:USERPROFILE\nexus-pc\windows\Nexus.DevClient\bin\Debug\net10.0\Nexus.DevClient.exe"
```

```powershell
& $nx send apps.list --host 127.0.0.1
```

Запуск программы по её `id` из `apps.list` (например, `steam`):

```powershell
& $nx send apps.launch --app steam --host 127.0.0.1
```

```powershell
& $nx send profiles.run --profile gaming --host 127.0.0.1
```

```powershell
& $nx send power.lock --host 127.0.0.1
```

## 8. Подсветка через OpenRGB (P10, по желанию)

Nexus PC управляет подсветкой через бесплатную программу **OpenRGB**. С 2026-11-18 OpenRGB 1.1 входит в `NexusPC-Setup.exe` и запускается службой сама (сервер только на `127.0.0.1:6742`); пункты 2–4 ниже нужны только при ручной установке без установщика. Окно OpenRGB для настройки устройств: значок «N» → «Настроить подсветку (OpenRGB)…».

1. **Armoury Crate** перехватывает подсветку ASUS и мешает OpenRGB. Закройте его, а в Armoury Crate → Настройки отключите запуск при старте (или удалите Aura/Lighting-службу, если подсветка всё равно сбрасывается).
2. Запустите OpenRGB **от имени администратора** (нужно для подсветки платы). Проверка, что SDK-сервер слушает (в OpenRGB 1.0 отдельной галочки нет, сервер был включён сразу): `Get-NetTCPConnection -LocalPort 6742 -State Listen` → строка `127.0.0.1 6742 Listen`. Если плата не появляется, установите драйвер **PawnIO** по инструкции на openrgb.org — с версии 1.0 OpenRGB использует его для доступа к SMBus.
3. Вкладка **SDK Server** → **Start Server**.
4. В настройках OpenRGB (**Settings → General**) включите запуск при входе, свёрнутый запуск и запуск сервера (названия пунктов — *Start At Login*, *Start Minimized*, *Start Server*; если в вашей версии они называются иначе, пришлите снимок экрана).
5. **Вентиляторы и кулер на разъёмах ARGB платы** (у ASUS — зоны «Addressable RGB Header 1/2/3»): OpenRGB не знает длину подключённых лент и считает её 0, поэтому они не горят. Вкладка **Devices** → плата → **Zone** → каждый «Addressable RGB Header» → **Edit Device** → число светодиодов (например, 60) → сохранить. Проверено на ASUS PRIME B660M-A WIFI D4: после этого вентиляторы и кулер управляются и из OpenRGB, и с iPhone.
6. На iPhone: Home → «Подсветка».

Подсветку монитора **Skydimo** OpenRGB не поддерживает — она остаётся в приложении Skydimo.

Порт 6742 в брандмауэре **не открывайте** — он нужен только внутри ПК.

## Восстановление папки данных

В `C:\ProgramData\NexusPC` хранятся сопряжённые устройства, настройки, сертификат, автоматизации и настройки подсветки. Доступ к папке должен быть только у системы (SYSTEM) и администраторов.

**Что проверяется.** При каждом запуске служба проверяет всю папку и ничего в ней не меняет:
- владелец каждого файла и папки — система, администраторы или TrustedInstaller;
- доступ разрешён только им;
- внутри нет ссылок любого вида (ярлыки-ссылки, точки соединения, файлы облачных хранилищ, которые ещё не скачаны);
- у файлов нет второго имени в другом месте диска (жёсткой ссылки);
- в `OpenRGB\plugins` ничего нет. Пустую папку `plugins` OpenRGB создаёт сам, когда открывается его окно; она допустима и не переименовывается.

Если что-то не так, служба не запускается. Список проблем она записывает в журнал Windows: «Просмотр событий» → «Журналы Windows» → «Приложение», источник `Nexus.Agent`, код 1001.

Если папки нет, служба и установщик создают её сразу защищённой. Если папка уже есть, установщик до любых изменений на диске (и до остановки службы) проверяет её так же, как служба. При проблемах установка останавливается с кодом выхода **6**: ничего не записано, служба не остановлена, на экране список проблем и что делать.

Все команды ниже запускаются в командной строке, открытой **от имени администратора** (иначе защищённые файлы не прочитать). Если Nexus PC ещё не установлен, вместо `Nexus.Agent.exe datadir <команда>` используйте установщик: `NexusPC-Setup.exe --datadir-check`, `--datadir-repair`, `--datadir-repair --continue "<папка копии>"`, `--datadir-restore-acl "<папка копии>"`, `--datadir-finalize "<папка копии>"`. Это тот же код, коды выхода те же.

**Проверить** (ничего не меняет):

```powershell
& "C:\Program Files\NexusPC\Agent\Nexus.Agent.exe" datadir check
```

**Исправить.** Выйдите из учётных записей других пользователей этого ПК, включая отключённые сеансы («Диспетчер задач» → «Пользователи»), и остановите службу:

```powershell
sc.exe stop NexusPCAgent
```

```powershell
& "C:\Program Files\NexusPC\Agent\Nexus.Agent.exe" datadir repair
```

Команда работает по шагам и на любом шаге может отказаться. Если она отказалась до создания копии, папка данных не изменена.
1. Проверяет, что служба остановлена (сама её не запускает), что не работает ни один агент Nexus PC (нет его каналов связи, нет процессов `Nexus.Agent.exe` и `OpenRGB.exe` из `Program Files\NexusPC`), что на ПК вошёл только один пользователь и именно в этом окне, и что нет незавершённого восстановления.
2. Проверяет всю папку, а также папку `C:\ProgramData`, где будет копия. Если найдена ссылка, жёсткая ссылка или неожиданный объект, команда отказывается: такие случаи нужно разобрать вручную.
3. Показывает, что лежит в папке: сопряжённые устройства (имя, дата, разрешения, начало отпечатка ключа), путь к трею и сертификат из настроек, непустую папку плагинов OpenRGB, посторонние файлы. В этот момент запоминается SHA-256 каждого файла: если до копирования файл изменится, команда откажется. Исправление прав не делает содержимое надёжным: если права были открыты, кто-то мог добавить устройство или поменять настройки. Продолжить можно, только введя слово `REPAIR`.
4. Проверяет место на диске: нужно не меньше размера папки × 1,1 + 50 МБ. Если места мало, команда ничего не создаёт.
5. Делает резервную копию `C:\ProgramData\NexusPC.backup-<дата-время>-<случайный суффикс>`: она сразу закрыта для всех, кроме системы и администраторов. Для каждого файла считается SHA-256 оригинала и копии. Опись копии сохраняется в `backup-manifest.json`, её SHA-256 выводится на экран. Если копирование не удалось, неполная копия остаётся с окончанием `.incomplete`, папка данных не меняется.
6. Сохраняет исходных владельцев, группы и права каждого объекта в `original-security.json` внутри копии. Каждая запись привязана к идентификатору файла на диске (номер тома и номер файла), а не только к пути. Ход работы записывается в `repair-journal.json` там же, вместе с исходным типом запуска службы Nexus PC. Затем служба переводится в «Отключена»: до завершения восстановления она не запустится сама, даже после перезагрузки.
7. Меняет права. Перед каждым изменением заново проверяются условия из шага 1; если они нарушены, команда останавливается. Каждый объект открывается заново и сверяется с проверкой из шага 2 (тот же объект, тот же тип, одна ссылка, тот же путь, права не менялись). Если что-то изменилось, команда останавливается. Непустая папка `OpenRGB\plugins` переименовывается в `plugins.disabled-<дата-время>` (карантин); её содержимое никогда не удаляется автоматически.
8. Проверяет результат: папка проходит проверку, сама папка данных закрыта от наследования прав, каждый файл совпадает с описью копии. Только после этого возвращает службе исходный тип запуска. Резервная копия не удаляется.

Затем проверьте устройства в трее («Устройства и разрешения…»), удалите незнакомые и запустите службу:

```powershell
sc.exe start NexusPCAgent
```

**Если восстановление прервалось** (сбой, выключение), `datadir check` и `datadir repair` сообщат о нём. Есть два пути:
- продолжить: `Nexus.Agent.exe datadir repair --continue "<папка копии>"` (каждый шаг снова проверяет свой объект);
- вернуть исходные права: `Nexus.Agent.exe datadir restore-acl "<папка копии>"`. Права возвращаются только тем объектам, у которых совпадает идентификатор. Содержимое не трогается. Восстановление после этого **не считается завершённым**: служба остаётся отключённой и заблокированной, исходный тип запуска остаётся сохранённым в журнале (см. «Завершение восстановления»).

Пока восстановление не завершено, служба отключена. Даже если включить её вручную, она не запускается: при старте она **первым делом** находит незавершённый журнал в доверенной копии и записывает в журнал Windows («Приложение», источник `Nexus.Agent`, код 1001) причину и точную команду завершения. Только если незавершённых восстановлений нет, служба проверяет саму папку. Это сохраняется после перезагрузки. Если служба не была отключена (не удалось сменить тип запуска), команда так и пишет, указывает реальный тип запуска и в папке ничего не меняет.

#### Завершение восстановления

Служба снова может запуститься только после полного завершения процедуры. Исходный тип запуска возвращается последним шагом, после всех проверок, и только затем восстановление отмечается завершённым. Пути к завершению:
- **После прерывания:** `datadir repair --continue "<папка копии>"`. Команда доделывает шаги, проверяет результат и сама завершает восстановление.
- **После `restore-acl`:** права снова исходные, папка проверку не проходит. Есть два пути:
  - запустить новое `datadir repair`. Оно берёт сохранённый исходный тип запуска из прежней копии, а когда завершится, отмечает прежнее восстановление как «superseded»;
  - если папка исправлена вручную, но только права, а содержимое не менялось: `datadir finalize "<папка копии>"` (в установщике — `NexusPC-Setup.exe --datadir-finalize "<папка копии>"`).
- **Если в конце не удалось вернуть тип запуска:** повторите `datadir repair --continue` или `datadir finalize` для той же копии.

`datadir finalize` выполняет проверки по порядку:
1. те же условия, что и восстановление: консоль администратора, служба остановлена, агента нет, вошёл только один пользователь;
2. копия доверенная, её журнал не изменён, и нет других незавершённых восстановлений, кроме тех, что эта копия взяла на себя (иначе отказ с перечнем копий и команд их завершения);
3. папка проходит строгую проверку: владельцы и права только у SYSTEM, администраторов и TrustedInstaller, корень защищён от наследования, нет ссылок, жёстких ссылок и файлов в `plugins`;
4. каждый файл папки и каждый файл копии совпадают с описью `backup-manifest.json`.

Только после этого `datadir finalize` возвращает исходный тип запуска и отмечает восстановление завершённым. Непосредственно перед возвратом типа запуска условия из п. 1 проверяются ещё раз (так же и в конце `repair --continue`). При любой ошибке ничего не меняется (или не ставится отметка о завершении), служба остаётся отключённой и заблокированной, код выхода ненулевой.

Если новое восстановление отказалось до изменений (например, не удалось отключить службу), его копия переименовывается в `.incomplete` и ничего не блокирует. Если переименовать её не удалось, команда прямо сообщает, что эта копия блокирует запуск службы, и называет команду `datadir repair --continue "<папка копии>"` (код 3).

Ни одна из команд не удаляет резервную копию и не запускает службу. `--purge` установщика копии тоже не удаляет.

Как команды и служба относятся к папкам `NexusPC.backup-…` рядом с папкой данных:
- **Владелец не администраторы и не система** (так бывает с папкой, созданной обычным пользователем). Это чужая папка: она показывается как «foreign folder, not used». Её содержимое не просматривается, она нигде не используется и ничего не блокирует.
- **Владелец — администраторы или система, внутри есть журнал, и папка проходит проверку.** Это настоящая копия. Если восстановление по ней не завершено, служба не запускается.
- **Владелец — администраторы или система, внутри есть журнал, но папка проверку не проходит.** Например, Проводник при «Продолжить» добавил право для вашей учётной записи, или журнал заменён ссылкой. Это относится и к копии уже завершённого восстановления: отметке «completed» в изменённом журнале не доверяют. Такая копия считается изменённой («tampered»): её журналу не доверяет ни одна команда, а служба и установщик **остаются заблокированными** (отказ при сомнении). Как выйти:
  1. проверьте папку вручную;
  2. переименуйте её от имени администратора так, чтобы имя больше не начиналось с `NexusPC.backup-` (например, `NexusPC-tampered-backup-<дата>`). Удалять не нужно;
  3. выполните `datadir check`. Дальше папка данных должна пройти проверку сама, при необходимости — новым `datadir repair`.

  Если служба при этом осталась отключённой, тип запуска верните вручную («Службы» → «Nexus PC Agent» → «Тип запуска»). Такую же блокировку может вызвать перенесённая чужая папка администратора — см. «Остаточные риски и ограничения Windows».
- **Больше 10 000 папок `NexusPC.backup-…` с владельцем «Администраторы» или «Система».** Решить безопасно нельзя: среди них могла бы спрятаться настоящая незавершённая копия. Поэтому всё блокируется, пока лишние папки не удалены. Папки обычных пользователей в этот предел не входят. На каждую папку уходит одно открытие корня, без обхода содержимого.
- **Окончание `.incomplete`** — неполные копии без изменений папки данных. Они не открываются и не учитываются.

Одновременно может работать только одно из трёх: команда `datadir` (в агенте или установщике), установка или удаление. Они делят одну защищённую блокировку — мьютекс в закрытом пространстве имён Windows, доступном только системе и повышенным администраторам; обычный пользователь не может заранее занять её имя. Если блокировка занята, `datadir` отказывает с кодом 1, установщик — с кодом 7. Ничего не меняется. Если защищённую блокировку не удаётся создать или открыть, отказ такой же, но с отдельным сообщением. Найденный или созданный мьютекс используется, только если его владелец — система или администраторы, а список доступа защищён и разрешает доступ только им. Иначе — отказ как при недоступной блокировке; ничего не меняется. Команда `datadir check` тоже работает под этой блокировкой и требует консоль администратора.

Удаление (`--uninstall`, `--purge`) отказывается с кодом 6, пока восстановление не завершено (в том числе по изменённой копии). Ничего не удаляется, на экран выводятся команды завершения. Если службы уже нет (её удалили вручную или старой версией установщика), `datadir finalize` и `repair --continue` после всех проверок завершают восстановление без возврата типа запуска.

`datadir finalize` принимает восстановление в любом незавершённом состоянии (прервано, остановлено, после `restore-acl`, тип запуска не вернулся) и для всех выполняет одни и те же проверки.

### Остаточные риски и ограничения Windows

Эти ограничения не устраняются программно; их снижают перечисленные проверки, а строгий вариант — офлайн-восстановление.
- **Гонка между проверкой и изменением.** Между проверкой и изменением прав проходит время. Каждый объект перед изменением открывается заново и сверяется (тот же объект, тот же тип, одна ссылка, тот же путь, права не менялись), а условия шага 1 проверяются снова. Полностью исключить изменение в промежутке программа не может.
- **Открытие по имени, а не относительно родителя.** Объекты открываются по полному пути (с префиксом `\\?\`, без следования по ссылкам) и сверяются по идентификатору и итоговому пути. Открытие относительно уже открытой родительской папки (запрет ссылок на уровне ядра) не реализовано. Это остаточный риск: подмену родительской папки между проверками ловит только повторная сверка.
- **Один вошедший пользователь — снижение риска, не гарантия.** Службы, запланированные задачи и программы, запущенные под той же учётной записью, что и окно администратора, продолжают работать.
- **Открытые дескрипторы.** Программа, которая уже держит открытым файл в папке, сохраняет доступ к нему и после смены прав. Поэтому после восстановления — перезагрузка.
- **Обход проверки прохода.** Windows по умолчанию разрешает проходить через закрытую папку к вложенному объекту, у которого свои разрешающие права. Поэтому, пока объект не обработан, закрытая папка сверху его не защищает.
- **Сеансы удалённого рабочего стола.** Служебные сеансы без пользователя (сеанс служб, прослушивающий сеанс RDP) не считаются. Любой сеанс с пользователем, в том числе отключённый, блокирует восстановление. Если не удаётся прочитать пользователя сеанса, это тоже отказ.
- **Каналы агента.** Существующий канал `NexusPC.Admin` или `NexusPC.Session` — отказ, даже если не удалось узнать его процесс-сервер (канал занят или закрыт для этой учётной записи).
- **Отключение службы.** Тип запуска службы меняется через диспетчер служб. Администратор может вручную включить и запустить службу во время восстановления. Тогда служба откажется стартовать, пока журнал восстановления не завершён (в том числе после `restore-acl`). Если сменить тип запуска не удалось, команда не начинает изменений и сообщает реальный тип запуска.
- **Много поддельных папок копий.** В `C:\ProgramData` любой пользователь может создавать папки. Папки, владелец которых — обычный пользователь, не просматриваются (одно открытие корня на каждую), не учитываются в пределе и ничего не блокируют: ни запуск службы, ни установку, ни удаление. В пределе 10 000 учитываются только папки `NexusPC.backup-…` с владельцем «Администраторы» или «Система»; создать такие может только администратор. Остаточный риск: очень большое число чужих папок замедляет проверку при старте, по одному открытию на папку.
- **Перенесённая чужая папка администратора (остаточный риск Medium, QA-T4-R6-1, принят владельцем).**
  - **Условия.** На том же томе, что и `C:\ProgramData`, есть папка, владелец которой «Система» или «Администраторы». Человеку без прав администратора полный доступ к ней не нужен, достаточно двух прав:
    - право перенести папку: «Удаление» на самой папке или «Удаление подпапок и файлов» у её родительской папки;
    - право создать в ней файл.
  - **Реалистичный пример.** Папки, которые повышенный процесс (установщик, программа «от имени администратора») создаёт в профиле самого администратора, например в `%TEMP%`. Их владелец — «Администраторы», а у обычного (неповышенного) токена того же пользователя к ним полный доступ. Значит, программа, запущенная этим пользователем без повышения, может перенести такую папку в `C:\ProgramData\NexusPC.backup-…` (владелец при переносе сохраняется) и положить туда `repair-journal.json`.
  - **Последствия.** Папка считается изменённой копией. До вмешательства администратора блокируются запуск службы, установка, удаление программы и новое `datadir repair`. Хватает одной такой папки, предел 10 000 здесь не помогает. Обхода защиты нет: служба не запускается с непроверенной папкой данных, права и данные не меняются. Отличить такую папку от настоящей копии, изменённой в Проводнике, по владельцу и правам нельзя.
  - **Восстановление** — то же, что для изменённой копии: проверить папку, переименовать её от имени администратора так, чтобы имя не начиналось с `NexusPC.backup-`, затем `datadir check`.
  - **Устранение** (защищённая отметка восстановления в разделе реестра службы, доступном только администратору) запланировано отдельной задачей.
- **Проверено только в CI.** Поведение на настоящем NTFS (владельцы, защищённый DACL, ссылки, жёсткие ссылки, тип запуска) проверяют Windows-тесты в CI windows-latest. На других версиях Windows и файловых системах (ReFS, сетевые диски) оно не проверялось.

**Офлайн-восстановление — отдельный, более строгий вариант.** Восстанавливать папку можно, когда эта копия Windows не запущена, например с диском, подключённым к другому доверенному ПК. Тогда на проверяемом диске не работают ни службы, ни другие пользователи. На доверенном ПК действуют те же условия: консоль администратора, служба Nexus PC (если она там есть) остановлена, вошёл только один пользователь. Последняя часть пути обязательно `NexusPC`:

```powershell
& "<доверенная копия>\Nexus.Agent.exe" datadir repair --data-dir "E:\ProgramData\NexusPC"
```

Берите `Nexus.Agent.exe` (или `NexusPC-Setup.exe --datadir-repair --data-dir …`) из доверенного источника, а не с проверяемого диска. Этот вариант выполняется вручную и в CI не проверяется. Если `--data-dir` указывает не на местную папку `C:\ProgramData\NexusPC`, тип запуска местной службы Nexus PC не меняется и не возвращается: к этой папке она отношения не имеет.

**Отмена всего.** Прежнюю версию программы можно вернуть, запустив её установщик. Права после восстановления возвращает `restore-acl` (затем — «Завершение восстановления»), а данные остаются в резервной копии.

## Известные ограничения

- Поиска ПК в сети (Bonjour) пока нет (P2).
- Без запущенного трея блокировка, приложения и профили отвечают `session.unavailable`, а обычное выключение идёт через службу с отсчётом 30 секунд.
- Приложения Microsoft Store запускаются, но закрыть их с телефона нельзя (неизвестен их .exe).
