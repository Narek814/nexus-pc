# Nexus PC — общие правила для всех субагентов

Этот файл обязателен для каждого агента из `.claude/agents/`. Прочитай его целиком **до начала работы**. Если правила здесь и в файле агента расходятся, действует более строгое. `CLAUDE.md` описывает только порядок работы главной сессии и ссылается на этот файл. Источник правил один — этот файл.

## 1. Что такое Nexus PC (кратко)

Приложение для iPhone управляет Windows-компьютером по домашней сети. Сейчас проект превращается в публичный продукт: сначала App Store, Android — позже. План и решения — `docs/COMMERCIAL_PLAN.md`.

| Часть | Где | Суть |
|------|-----|------|
| Протокол v1 | `shared/schemas/`, `shared/protocol/fixtures/`, `docs/API.md` | JSON поверх WSS. Это единственный источник правды; одни и те же фикстуры проверяют и C#, и Swift. |
| Nexus.Core | `windows/Nexus.Core` | Протокол, каталог команд, разрешения, сопряжение, QR. Кроссплатформенный, тестируется на Linux. |
| Nexus.Agent | `windows/Nexus.Agent` | Служба Windows (LocalSystem), Kestrel WSS на порту 47800, только частные адреса, аудит, автоматизации, история. |
| Nexus.Tray | `windows/Nexus.Tray` | WinForms в сеансе пользователя. Связь со службой — канал `NexusPC.Session`. |
| Nexus.Setup | `windows/Nexus.Setup` | Установщик. .NET, OpenRGB 1.1 и PawnIO внутри, закреплены по SHA-256. |
| Прочее Windows | `Nexus.Windows`, `Nexus.Monitoring`, `Nexus.RGB`, `Nexus.DevClient` | Вызовы Windows, датчики, OpenRGB SDK, тестовый клиент. |
| iOS | `ios/NexusKit` (логика), `ios/NexusPC` (SwiftUI), `ios/NexusWidgets`, `ios/project.yml` (XcodeGen) | iOS 17+. Ключ P-256 в Secure Enclave, pinning сертификата ПК. |
| CI | `.github/workflows/ci.yml`, `ios.yml` | Linux + Windows (.NET, установщик), macOS (Swift-тесты, IPA без подписи). |

Ключевые решения — `ARCHITECTURE.md`, раздел 2:
- D1: служба не запускает GUI.
- D2: белый список команд, никаких shell и PowerShell.
- D3: один протокол для всех клиентов.
- D4: QR-сопряжение, pinning, Secure Enclave.
- D10: каждая новая зависимость — только с одобрения владельца.
- D11: нулевой бюджет.
- D12: Mac нет, iOS собирается только в GitHub Actions.

Модель угроз — в `SECURITY.md`. Реальный статус функций — в `FEATURES.md`.

## 2. Абсолютные запреты (без явного разрешения владельца)

1. **Не удалять и не отключать работающие функции.** Это касается в том числе функций со статусом ✅ в `FEATURES.md`. Рефакторинг допустим, только если поведение сохраняется и это подтверждают тесты.
2. **Не менять протокол.** Сюда входят схемы, типы сообщений, поля, коды ошибок, формат сопряжения и входа, строки подписи и порт. Изменение идёт только через одобренный владельцем план `code-architect` (раздел 8).
3. **Не делать необратимых и внешних действий:**
   - force-push, удаление веток и тегов, создание тегов, `reset --hard`, `clean -f`;
   - публикация релизов, загрузка в App Store Connect, TestFlight или Google Play;
   - `--purge` установщика вне CI;
   - изменение настроек и секретов GitHub-репозитория;
   - отправка данных во внешние сервисы.
4. **Не подключать платные сервисы, подписки и платные API.** Также не создавать в них аккаунты.
5. **Не менять Bundle ID** (`io.github.narek814.nexuspc`, `…nexuspc.widgets`) и настройки подписи. **Не вступать в Apple Developer Program.** Публикация в App Store — последний этап проекта, решение принимает владелец.
6. **Не создавать фиктивные функции.** Никаких заглушек, которые выглядят как работающие, выдуманных значений датчиков (D9), «зелёных» тестов без проверки и статуса ✅ без проверки владельцем на устройствах.
7. **Не добавлять внешние зависимости** (NuGet, SwiftPM, npm, pip в продукт) — D10.
8. **Не ослаблять безопасность.** Не трогать pinning, проверку подписи, ACL каналов, правило брандмауэра «только частная сеть» и белый список команд. Не прятать проверки за флагами отладки.
9. **Не пропускать, не отключать и не удалять тесты**, чтобы получить зелёный CI.
10. **Секреты не попадают в репозиторий.** Это ключи, токены, пароли, `service_role`, сертификаты и профили.

## 3. Роли

| Тип | Агенты | Права |
|-----|--------|-------|
| **Агенты анализа** | `code-architect`, `security-auditor`, `qa-engineer` | Файлы проекта не меняют. Можно: чтение, `git status/log/diff/show/blame`, сборка и тесты (вывод в `bin/`, `obj/`, `TestResults/`), временные файлы в `/tmp` и scratchpad. |
| **Агенты с правом записи** | `ios-developer`, `windows-developer`, `android-developer`, `backend-developer`, `web-developer`, `ui-ux-designer`, `release-manager` | Меняют только файлы своей зоны (раздел 5). |

Для всех субагентов:
- **Git только для чтения.** Коммиты, ветки, push, stash, checkout и прочие изменения git делает только главная сессия.
- **Субагент не может задать вопрос пользователю.** Если нужна правка вне зоны, решение владельца или противоречие в задании, агент **останавливается** и возвращает отчёт с пометкой `НУЖНО РЕШЕНИЕ: …`. Именно это и значит «согласовать с главным Claude Code».
- Меняй минимально и в стиле окружающего кода. Комментарии в коде — по-английски, как в проекте. Пользовательские документы — по-русски, понятным языком.

## 4. Проверки и среда

| Что | Команда | Где реально работает |
|-----|---------|----------------------|

Если `command -v dotnet` пуст, поставь сам: `curl -fsSL https://dot.net/v1/dotnet-install.sh -o /tmp/dotnet-install.sh && bash /tmp/dotnet-install.sh --channel 10.0 --install-dir "$HOME/.dotnet"`. Windows-специфичные тесты, установщик и H.264 — только CI `windows-latest`. |
| Схемы | `python3 -I tools/check_fixtures.py` | Где угодно. `jsonschema` ставь во временный venv: `python3 -m venv /tmp/qa-venv && /tmp/qa-venv/bin/pip install "jsonschema>=4.18,<5"`, затем запускай `/tmp/qa-venv/bin/python -I tools/check_fixtures.py`. |
| QR | `python3 -I tools/check_qr.py` | Облачная среда: в тот же venv `/tmp/qa-venv/bin/pip install "zxing-cpp>=2.2,<3" "pillow>=10"`, запуск `/tmp/qa-venv/bin/python -I tools/check_qr.py` (нужен .NET). |

Инструменты для проверок ставятся **вне репозитория**: во временный venv, `~/.dotnet`, `~/.cache`. Пакеты в проект не добавляются. Если проверку нельзя запустить, скажи это прямо и укажи, где она выполнится. Не утверждай, что она прошла.

## 6. Параллельность

- По умолчанию в каждый момент работает один агент. Несколько агентов одновременно — только с отдельного разрешения владельца. QA и Security проверяют последовательно, после завершения разработки.
- **В каждый момент файлы проекта меняет только один агент с правом записи.** Это закреплено технически (раздел 9): второй агент получит отказ. Получив отказ, остановись и сообщи о нём.
- Если ты видишь незакоммиченные изменения в файлах, которые собираешься править, и не ты их сделал, остановись и сообщи.

## 7. Отчёт агента

В конце работы агент сообщает:
1. Что сделано или найдено. Ссылки давай в виде `путь:строка`.
2. Что изменено — список файлов или «ничего».
3. Какие проверки выполнены, их результат. Отдельно — что не проверено и почему.
4. `НУЖНО РЕШЕНИЕ: …` — что требует решения главной сессии или владельца, если такое есть.

Отчёт пишется для главного Claude Code: коротко, по фактам, без выдуманных результатов. Не пересказывай историю задачи и содержимое файлов.

## 7а. Экономия лимита (без ущерба качеству и безопасности)

- Читай только файлы, относящиеся к задаче, и только нужные фрагменты больших файлов. Не перечитывай репозиторий и не ищи по всему проекту без причины. Не повторяй анализ неизменённого кода.
- Делай только поставленную задачу: без лишних функций, рефакторинга и изменений архитектуры. Предпочитай небольшие локальные правки и существующие механизмы, не создавай дубликатов.
- Тесты: сначала относящиеся к изменённому коду, затем интеграционные при необходимости, полный набор — на контрольных этапах и не повторно без изменений. Не пересобирай без изменений кода или конфигурации.
- Различай реальные Windows-тесты и тесты, которые на Linux лишь завершаются ранним выходом. Не называй Windows-функциональность проверенной, пока Windows-тесты реально не выполнены.
- Экономия никогда не оправдывает ослабление безопасности, удаление или пропуск проверок и тестов, сокрытие ошибок, обход ограничений проекта. Если для безопасности нужны дополнительные проверки — выполни их и объясни причину.
- Проблему вне текущей задачи — сообщи отдельно, не исправляй. Слишком большую задачу — сначала раздели на этапы и предложи экономный порядок.
- Главная сессия (решение владельца 2026-11-23): QA — на каждое крупное задание; мелкие правки (тесты, комментарии, одна-две строки) главная сессия проверяет сама прогоном тестов. Аудит security-auditor — один раз на этап или на изменение, затрагивающее безопасность, а не на каждую правку. Исправления после аудита и замечания QA — одним заданием. На события PR не подписываться без отдельной просьбы: CI проверять вручную после итогового коммита. Новый этап — новая сессия с короткой сводкой (`.claude/handoff/SESSION-SUMMARY.md`).
- Эти правила не расширяют полномочий (раздел 2).

## 7б. HybridAI (локальная модель)

- **Назначение — экономия лимита Claude.** HybridAI — вспомогательная система, а не цель разработки. Не улучшать, не перенастраивать и не чинить её без отдельной задачи владельца. Если она недоступна — работай обычным способом.
- **Researcher** — предварительный анализ и рутинная работа, и только когда это действительно экономит лимит Claude. Передавай вопрос, точный список файлов или фрагментов и требуемый формат ответа: минимально необходимые файлы и контекст, без всего репозитория. Не передавай повторно уже проанализированные материалы без причины.
- **Формат ответа Researcher:** до одного экрана; каждый вывод — `путь:строка`, дословная цитата, уверенность (высокая/средняя/низкая); «не знаю» допустимо.
- **Проверка Claude:** важные выводы и цитаты проверяются точечным чтением указанных строк. Неподтверждённое отбрасывается. Подтверждённый отчёт используется вместо повторного самостоятельного анализа тех же материалов.
- **Reviewer HybridAI не является финальным проверяющим.** Его замечания — только черновой список для проверки Claude.
- **Код, архитектура, решения по безопасности, финальные QA и Security** — только Claude. Выводы Researcher о безопасности Win32, криптографии и правах доступа без проверки не принимаются.
- **Без разрешения владельца** HybridAI не меняет файлы, не выполняет команды и Git-операции и не получает доступ к новым файлам или каталогам. Все ограничения доступа и разделы 2 и 7а сохраняются.
- **Не передавать** HybridAI секреты, ключи, пароли и личные данные, а также данные вне проекта.

## 8. Передача задач (архитектор → исполнитель → QA)

Субагенты не общаются друг с другом и не видят чужих отчётов. Всё передаётся через главную сессию, поэтому каждое задание должно быть **самодостаточным**.

1. **`code-architect`** заканчивает план блоками «Задание», по одному на исполнителя:
   ```
   ЗАДАНИЕ <ID>: <кратко>
   Исполнитель: <агент>
   Файлы: <пути>
   Сделать: <шаги>
   Не трогать: <что сохранить>
   Критерии приёмки: <проверяемые условия>
   Тесты: <какие добавить/запустить>
   Зависит от: <ID или «нет»>
   ```
2. **Главная сессия** согласует план с владельцем, если затронуты протокол, зависимости, безопасность или удаление функциональности. Затем передаёт исполнителю блок «Задание» **дословно**.
3. **Исполнитель** выполняет задание и заканчивает отчёт блоком:
   ```
   ПЕРЕДАЧА В QA <ID>
   Изменённые файлы: <пути>
   Что проверить: <критерии приёмки из задания>
   Запущено: <команды и результат> / Не запускалось: <что и почему>
   ```
4. **`qa-engineer`** получает блок «Передача в QA» и возвращает вердикт: `ПРИНЯТО`, `НЕ ПРИНЯТО` (с причинами и `путь:строка`) или `НЕ ПРОВЕРЕНО ЗДЕСЬ` (где проверится). Код недостающих тестов QA прикладывает в отчёте; добавляет их исполнитель (следующее задание).
5. Если затронута безопасность, после QA запускается `security-auditor` по тому же списку файлов.

## 9. Технические ограничения (не только инструкции)

| Механизм | Что делает |
|----------|-----------|
| Список `tools` в frontmatter | у агентов анализа нет Write/Edit; ни у одного агента нет Agent (нельзя запускать других агентов); инструменты GitHub — только чтение |
| Хук `.claude/hooks/agent_guard.py` (`.claude/settings.json`, PreToolUse для Edit/Write/MultiEdit/NotebookEdit/Bash) | по `agent_type` применяет зоны раздела 5 к файлам и к командам Bash (перенаправления, `rm`/`mv`/`cp`/`tee`/`sed -i`, встроенные скрипты); запрещает субагентам изменения git, необратимые действия, отправку данных наружу, добавление зависимостей, правку Bundle ID и подписи, секретные файлы; держит блокировку «один пишущий агент» |
| Главная сессия | на необратимые действия, правку Bundle ID и подписи, секретные файлы хук выдаёт **запрос подтверждения** вместо отказа |
| Сбой хука | `onFailure: block`: если охранник не запустился, действие блокируется, а не пропускается |

Разбор shell-команд эвристический. Обходить охранника, например через обфусцированные команды, запрещено правилами. Любой отказ охранника — сигнал остановиться и сообщить, а не искать обход. Журнал решений — `/tmp/nexus-agent-guard.log`.
