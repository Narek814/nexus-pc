# Nexus PC — общие правила для всех субагентов

Этот файл обязателен для каждого агента из `.claude/agents/`. Прочитай его целиком **до начала работы**. Если правила здесь и в файле агента расходятся, действует более строгое.

## 1. Что такое Nexus PC (кратко)

Приложение для iPhone управляет Windows-компьютером по домашней сети. Сейчас проект превращается в публичный продукт. Сначала App Store, Android — позже. План и решения: `docs/COMMERCIAL_PLAN.md`.

| Часть | Где | Суть |
|------|-----|------|
| Протокол v1 | `shared/schemas/`, `shared/protocol/fixtures/`, `docs/API.md` | JSON поверх WSS. Это единственный источник правды; одни и те же фикстуры проверяют и C#, и Swift. |
| Nexus.Core | `windows/Nexus.Core` | Протокол, каталог команд, разрешения, сопряжение, QR. Кроссплатформенный, тестируется на Linux. |
| Nexus.Agent | `windows/Nexus.Agent` | Служба Windows (LocalSystem), Kestrel WSS на порту 47800, только частные адреса, аудит, автоматизации, история. |
| Nexus.Tray | `windows/Nexus.Tray` | WinForms в сеансе пользователя. Связь со службой — канал `NexusPC.Session`. |
| Nexus.Setup | `windows/Nexus.Setup` | Установщик. .NET, OpenRGB 1.1 и PawnIO внутри, закреплены по SHA-256. |
| Прочее Windows | `Nexus.Windows`, `Nexus.Monitoring`, `Nexus.RGB`, `Nexus.DevClient` | Вызовы Windows, датчики, OpenRGB SDK, тестовый клиент. |
| iOS | `ios/NexusKit` (логика), `ios/NexusPC` (SwiftUI), `ios/NexusWidgets`, `ios/project.yml` (XcodeGen) | iOS 17+. Ключ P-256 в Secure Enclave, pinning сертификата ПК. |
| CI | `.github/workflows/ci.yml`, `ios.yml` | Linux + Windows (.NET, установщик), macOS (Swift-тесты, IPA без подписи). |

Ключевые решения — `ARCHITECTURE.md`, раздел 2:
- D1: служба не запускает GUI.
- D2: белый список команд, никаких shell и PowerShell.
- D3: один протокол для всех клиентов.
- D4: QR-сопряжение, pinning, Secure Enclave.
- D10: каждая новая зависимость — только с одобрения владельца.
- D11: нулевой бюджет.
- D12: Mac нет, iOS собирается только в GitHub Actions.

Модель угроз — в `SECURITY.md`. Реальный статус функций — в `FEATURES.md`.

## 2. Абсолютные запреты (без явного разрешения владельца)

1. **Не удалять и не отключать работающие функции.** Это касается в том числе функций со статусом ✅ в `FEATURES.md`. Рефакторинг допустим, только если поведение сохраняется и это подтверждают тесты.
2. **Не менять протокол.** Сюда входят схемы, типы сообщений, поля, коды ошибок, формат сопряжения и входа, строки подписи и порт. Можно предложить изменение через `code-architect`, но не вносить его самому.
3. **Не делать необратимых действий.** В том числе:
   - `git push --force`, `git reset --hard` по чужой работе, удаление веток и тегов;
   - публикация релизов, загрузка в App Store Connect или TestFlight;
   - удаление пользовательских данных, `--purge` на реальной машине;
   - изменение настроек GitHub-репозитория и секретов.
4. **Не подключать платные сервисы, подписки и платные API.** Также не создавать в них аккаунты.
5. **Не менять Bundle ID** (`io.github.narek814.nexuspc`, `…nexuspc.widgets`) и подпись. **Не вступать в Apple Developer Program и не готовить сборку к немедленной публикации.** Публикация в App Store — последний этап проекта, и решение о ней принимает владелец.
6. **Не создавать фиктивные функции.** Никаких заглушек, которые выглядят как работающие, выдуманных значений датчиков (D9), «зелёных» тестов без проверки и статуса ✅ без проверки владельцем на реальных устройствах.
7. **Не добавлять внешние зависимости** (NuGet, SwiftPM, pip в продукт) без одобрения — D10.
8. **Не ослаблять безопасность.** Не трогать pinning, проверку подписи, ACL каналов, правило брандмауэра «только частная сеть» и белый список команд. Не прятать проверки за флагами отладки.
9. **Не пропускать, не отключать и не удалять тесты**, чтобы получить зелёный CI.
10. **Секреты не попадают в репозиторий.** Это ключи, токены, пароли, `service_role` и сертификаты.

## 3. Работа с исходниками

- **Агенты анализа** (`code-architect`, `security-auditor`, `qa-engineer`) исходники не меняют. Если нужна правка, агент описывает её в отчёте: файл, строки, что и почему. Главный Claude Code согласует её и поручает исполнителю.
- **Агенты-исполнители** (`ios-developer`, `windows-developer`, `android-developer`) меняют только файлы своей зоны (раздел 5). Изменение за пределами зоны агент сначала согласует с главным Claude Code: сообщает, что нужно и зачем, и останавливается.
- `ui-ux-designer` пишет спецификации и меняет только `docs/design/`. Код по спецификации делает исполнитель платформы.
- `release-manager` меняет версии, CI-конфигурацию релиза и документацию релиза. Код продукта он не меняет.
- Меняй минимально и в стиле окружающего кода. Комментарии в коде — по-английски, как в проекте. Пользовательские документы — по-русски, понятным языком.
- **Не делай коммитов и не пушь**, если главный Claude Code не поручил это явно.

## 4. Проверки

| Что | Команда | Где работает |
|-----|---------|--------------|
| C# (475 тестов) | `dotnet test windows/Nexus.slnx` | Linux, если установлен .NET 10 SDK. Windows-специфичные тесты — только на Windows в CI. |
| Схемы | `python3 -I tools/check_fixtures.py` | Нужен `jsonschema`. |
| QR | `python3 -I tools/check_qr.py` | Нужны `zxing-cpp` и `pillow`. |
| Swift | `swift test --package-path ios/NexusKit` | Только macOS, то есть в CI `ios.yml`. Сборка IPA — тоже только там. |

Если проверку нельзя запустить в текущей среде, скажи это прямо и укажи, где она выполнится. Не утверждай, что она прошла.

## 5. Зоны ответственности (без пересечений)

| Агент | Решает | Не делает |
|-------|--------|-----------|
| code-architect | структура, границы модулей, протокол (только предложения), планы и порядок этапов | код, вердикт по безопасности, визуальный дизайн |
| security-auditor | угрозы, уязвимости, крипто, pairing, TLS, ключи, сторонние компоненты, лицензии компонентов | код, архитектурные планы вне безопасности |
| ios-developer | код `ios/**`, локализация iOS, производительность iOS | `windows/**`, `shared/**`, визуальные решения без спецификации |
| windows-developer | код `windows/**`, Tray, Installer, служба, локализация Windows | `ios/**`, `shared/**` без плана архитектора, workflow релиза |
| android-developer | будущий `android/**`, совместимость Android с протоколом | iOS/Windows-код, протокол |
| qa-engineer | запуск тестов, разбор CI, поиск ошибок, тест-планы и регрессии | правка кода и тестов (предлагает, а пишет исполнитель) |
| ui-ux-designer | дизайн-система, экраны, навигация, анимации, доступность, тексты интерфейса (спеки) | код Swift/C# |
| release-manager | версии, сборки, CI релиза, чек-листы, соответствие документации, готовность к релизу | код продукта, сама публикация |

`shared/schemas` и `shared/protocol/fixtures` меняются только по одобренному владельцем плану `code-architect`. Исполнитель вносит изменение синхронно в C# и Swift.

## 6. Параллельность

- Агенты анализа можно запускать параллельно.
- **Два агента, которые могут менять одни и те же файлы, одновременно не запускаются.** Исполнители работают по очереди.
- Если агент обнаружил незакоммиченные изменения в файлах, которые собирается править, и не он их сделал, он останавливается и сообщает об этом.

## 7. Отчёт агента

В конце работы агент сообщает:
1. Что сделано или найдено. Ссылки давай в виде `путь:строка`.
2. Что изменено — список файлов или «ничего».
3. Какие проверки выполнены, их результат. Отдельно — что не проверено и почему.
4. Что требует решения главного Claude Code или владельца.

Отчёт пишется для главного Claude Code: коротко, по фактам, без выдуманных результатов.
