# E4-6 — исправления по аудиту E4 (решения владельца 2026-11-25: S1 = А, S2 = А)

```
ЗАДАНИЕ E4-6: SYSTEM-only account.dat с миграцией (S1, S4) и вход/отвязка только для администраторов (S2)
Исполнитель: windows-developer
Файлы: windows/Nexus.Agent/Account/RefreshTokenStore.cs; windows/Nexus.Agent/Storage/EntitlementFileStore.cs и windows/Nexus.Core/Entitlements/EntitlementFilePolicy.cs (вынести общий хелпер CreateProtected/IsTrusted, поведение entitlement.json не менять); windows/Nexus.Core/Storage/DataDirectoryPolicy.cs; windows/Nexus.Windows/DataDirectoryFileSystem.cs (только при необходимости); windows/Nexus.Agent/Session/TraySessionServer.cs, windows/Nexus.Agent/Admin/** (AdminPipe/AdminService), windows/Nexus.Agent/Server/CommandDispatcher.cs при необходимости; windows/Nexus.Tray/AccountForm.cs, TrayContext.cs, TrayText.cs, Strings*.resx; windows/Nexus.Core/Account/AccountLoginModel.cs; тесты в windows/Nexus.Tests/.
Сделать:
S1/S4 — account.dat:
1. Save на Windows: account.dat.tmp создаётся сразу с защищённым DACL «только SYSTEM» (плюс тестовая учётка только при AgentPaths.TestTrustedSids), FileMode.CreateNew, запись + flush, затем атомарный rename/replace в том же каталоге (дескриптор сохраняется). Остатки .tmp от прошлых сбоев удаляются безопасно. Образец — EntitlementFileStore.CreateProtected, если подходит; если нет — объяснить в отчёте.
2. Load на Windows: до чтения проверить владельца (AgentPaths.TrustedSids), protected DACL и что allow-записи только из разрешённого набора. Доверенный SYSTEM-only → читать. Ожидаемый старый ACL (наследуемый, allow только SYSTEM + BUILTIN\Administrators, владелец SYSTEM или Administrators, без deny/иных SID) → прочитать один раз и сразу перезаписать через Save с SYSTEM-only DACL (refresh и вход сохраняются). Любой иной ACL (Users, Everyone, Authenticated Users, пользовательский SID, снят protected при наличии лишних записей, чужой владелец, ошибка чтения дескриптора) → не читать содержимое, удалить файл, audit "account.untrustedFile" ok:false без путей и содержимого, вернуть null (вход не выполнен, план Free). Ошибки ввода-вывода — безопасно, без падения службы.
3. DataDirectoryPolicy: account.dat (и account.dat.tmp) — DataSecurity.SystemOnlyFile в RepairSecurityFor, общая константа имени с RefreshTokenStore; scan не считает SYSTEM-only account.dat нарушением; после repair служба читает токен (вход сохраняется).
4. Диагностика/repair/бэкап не выводят содержимое account.dat (только хеш/размер, как прочие файлы). Проверить Nexus.Setup: если установщик/деинсталлятор трогает account.dat — сообщить, не менять; деинсталляция должна по-прежнему удалять файл.
S2 — административные действия:
5. login.start и unlink выполняются только для администраторов Windows. Проверка — на стороне службы по реальному токену процесса-клиента пайпа (имперсонация/токен клиента, членство в BUILTIN\Administrators с повышенным токеном, т.е. не отфильтрованный UAC-токен), не по полю запроса. Предпочтительно использовать существующий admin-пайп (AdminPipe: доступ только SYSTEM и повышенным администраторам) — перенести/продублировать туда login.start и unlink; в session-пайпе (TraySessionServer) эти команды отклонять кодом admin.required. login.status и просмотр плана/привязки остаются в session-пайпе для всех.
6. Трей: «Войти» и «Отвязать» запускают повышенный экземпляр Nexus.Tray.exe через UAC (Verb="runas", как в DevicesForm.cs:130 / TrayContext.cs:225) с аргументом действия; повышенный процесс выполняет команду через admin-пайп и показывает результат/userCode; отказ в UAC → понятное сообщение без ошибки. Обычный трей после этого продолжает опрос login.status (логика возобновления из E4-5a сохраняется: отметка «вход начат» пишется так, чтобы её видел обычный трей, без кодов). userCode не логируется и не передаётся через аргументы командной строки.
7. Тексты EN/RU для UAC и admin.required.
Не трогать: протокол сервера и backend/**, DPAPI-схему, entropy и формат account.dat, ACL корня каталога данных, поведение entitlement.json, PairingForm/QR, политику кодов pc-token (E4-4c), Nexus.Setup (только сообщить).
Критерии приёмки:
- После Save: account.dat protected, allow только S-1-5-18 (в проде), .tmp создаётся уже защищённым; запись атомарна.
- Старый ожидаемый ACL → токен прочитан, файл перезаписан SYSTEM-only, повторный Load проходит, вход сохранён.
- Неожиданный ACL (Users/Everyone/пользовательский SID/чужой владелец/ошибка дескриптора) → содержимое не читается, файл удалён, null, audit-событие; refresh нигде не логируется.
- repair ставит SystemOnlyFile на account.dat, вход сохраняется; тесты entitlement.json без изменений зелёные.
- login.start/unlink из session-пайпа → admin.required; из admin-пайпа (повышенный администратор) → работают; login.status из session-пайпа работает для всех; решение принимается по токену клиента.
- Трей: UAC-запуск, отказ UAC обрабатывается; userCode не в аргументах и не в логах; строки EN/RU.
Тесты: unit (Linux, фейковая ФС/политика): Save/Load/миграция/недоверенный ACL, маршрутизация команд по пайпам, модель трея; Windows-тесты реального DACL и токена клиента (IsElevated-гард, как в DataDirectoryWindowsTests) — проверятся в Windows CI. Полный dotnet test windows/Nexus.slnx -c Release.
Зависит от: E4-5a
```
