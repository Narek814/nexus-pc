# План E5 (дизайн) — утверждён владельцем 2026-11-25

E5 = спецификация в `docs/design/**` без кода (реализация — E6 и задания трея), плюс одно кодовое задание E5-0 (замечания QA по E4-6).
Порядок: E5-0 → QA → security-auditor (2 файла) → E5-1 → E5-2 → E5-3 → E5-4 → QA документов (одним прогоном) → E5-5 → главная сессия обновляет `docs/COMMERCIAL_PLAN.md`. Один агент одновременно. Протокол в E5 не меняется; пробелы — `НУЖНО РЕШЕНИЕ` в E5-5.
Конфликт COMMERCIAL_PLAN: раздел 0 (аккаунт обязателен) главнее раздела 5 («Пропустить») — кнопки пропуска нет; Free после настройки работает без интернета.

## Решения владельца (действуют)
userCode показывает обычное окно «Аккаунт», повышенный процесс без UI; отказ UAC = «Отменено»; отвязка на ПК локальная; почту аккаунта на ПК не показывать; без постоянной фоновой задачи входа. Утверждено: E5-0 удаляет account.dat > 8 КБ, при отказе в доступе не удаляет (audit); после QA E5-0 — короткая проверка security-auditor.

ЗАДАНИЕ E5-0: замечания QA по E4-6 (account.dat: Open/oversize; UAC: отказ vs ошибка; 2 теста)
Исполнитель: windows-developer
Файлы: windows/Nexus.Agent/Account/RefreshTokenStore.cs; windows/Nexus.Tray/ElevatedAccount.cs; windows/Nexus.Core/Account/AccountLoginModel.cs (и при необходимости ElevatedAccountCommand); windows/Nexus.Tray/TrayText.cs, Strings.resx, Strings.ru.resx (только если нужна новая строка); windows/Nexus.Tests/AccountFileAndAdminTests.cs (и тест модели трея).
Сделать:
1. RefreshTokenStore.Load, файл больше MaxBytes (8 КБ), независимо от вердикта Inspect: содержимое не читать, удалить файл (DeleteQuietly), вызвать onUntrusted (audit "account.untrustedFile" ok:false, без пути и содержимого), вернуть null. Обоснование: легитимный account.dat всегда < 1 КБ; больший файл — подмена или повреждение, вход всё равно невозможен, а молчаливый null оставлял мусор и не давал следа.
2. RefreshTokenStore.Load, UnauthorizedAccessException при Open или Inspect: служба работает под SYSTEM, поэтому отказ в доступе означает, что ACL/владелец изменены не нами. Поведение: вернуть null, файл НЕ удалять (удалить без прав всё равно нельзя, а попытка не должна маскировать проблему), вызвать отдельный audit "account.file" ok:false с кодом "account.accessDenied" (новый колбэк onAccessDenied или параметр причины у onUntrusted — на выбор, без путей). DataDirectoryPolicy repair по-прежнему восстанавливает ACL. Прочие IOException (занят, сбой диска) — как сейчас: null, без удаления, без audit (временная ошибка, следующая попытка пройдёт).
3. ElevatedAccountProcess.RunAsync: отказ UAC = только Win32Exception с NativeErrorCode == 1223 (ERROR_CANCELLED) → null (модель показывает «Отменено», как сейчас). Любой другой Win32Exception → ExitCodeOfError("failed") (модель показывает общую ошибку через Fail), с записью в лог трея только NativeErrorCode, без аргументов и userCode. Вынести классификацию в чистую функцию (например ElevatedAccountCommand.IsUacDeclined(int nativeError)) для unit-теста на Linux.
4. Тесты (добавить):
   - Oversized_trusted_file_is_deleted_unread_and_audited: доверенный (SYSTEM-only) файл > 8 КБ → Load == null, протектор Unprotect не вызывался, файл удалён, onUntrusted вызван один раз.
   - Legacy_rewrite_failure_keeps_the_token: вердикт Legacy, Save бросает IOException/UnauthorizedAccessException (фейковый IProtectedFileAccess.CreateNew) → Load возвращает токен, исходный файл не удалён, следующий Load снова пробует миграцию.
   - Access_denied_on_open_is_audited_and_not_deleted (по п.2).
   - Theory по IsUacDeclined: 1223 → true; 2, 5, 740, 1155 → false; модель: null → AdminDeclined, код "failed" → ошибка, не «Отменено».
Не трогать: формат и DPAPI/entropy account.dat, ACL-политику SYSTEM-only и миграцию legacy (кроме п.1–2), admin-пайп и проверку токена клиента, решение «userCode показывает обычное окно Аккаунт, повышенный процесс без UI», текст «Отменено», протокол v1 и backend/**, DevicesForm.cs (только сообщить, если там та же проблема).
Критерии приёмки: п.1–3 реализованы; refresh-токен и userCode нигде не логируются; новые тесты зелёные; полный dotnet test windows/Nexus.slnx -c Release зелёный (было 1260 на Linux).
Тесты: добавленные выше + полный набор; Windows-only тесты DACL — в Windows CI (PR #10).
Зависит от: нет

## Открытые решения владельца (рекомендации)
| Решение | Рекомендация | Блокирует |
|---|---|---|
| Домен и iss | купить до E8; iss = https://api.<домен>; до того {DOMAIN} | реальный сервер, {ACCOUNT_URL}, E8, E9 |
| Supabase | Free, ЕС (Франкфурт) | боевые тесты E6/E7 |
| anon-ключ | MSBuild NexusAccountAnonKey из CI-секрета, не в репозитории | сборку агента с аккаунтом |
| TLS pinning | агент: 2–3 промежуточных CA с запасными; iOS — системный TLS | E9 |
| Free/Pro | утвердить PROPOSED; screen.video → Pro; clipboard.*, history.list, delaySeconds → Free | E5-2 (оба варианта), E6 |
| LICENSE | проприетарная + файл третьих сторон с GPL-исходниками | экран лицензий, E9 |
| Юрлицо | страна с MoR (Paddle/Lemon Squeezy) и выплатами Apple; не РФ | E7, E8 |
| Оплата | сайт — MoR; iOS — StoreKit 2 | E7 |
| Цены/пробный период | решить к E7; заглушки | E7 |
| Повторный вход Apple при удалении | принимать oauth Apple со свежестью 300 с | E5-3 (помечено), backend до E6 |
| Лимиты (ПК, файлы Free) | параметры сервера, в UI без чисел | E5-2, E7 |

Примечание: полных текстов двух тестов QA в репозитории нет (E4-6.md:31 — только префиксы); в E5-0 они составлены по смыслу замечаний.
