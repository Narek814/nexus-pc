## Решения владельца по итогам E4-4b (2026-11-24)
1. Вход подтверждён на телефоне, трей закрыт до результата: при следующем запуске трея — понятное уведомление; если протокол позволяет безопасно — возобновить завершение входа, иначе предложить повторить вход; постоянный фоновый процесс не добавлять.
   Разбор: попытка входа (deviceCode) живёт в памяти службы, опрос идёт при login.status из трея. Перезапуск трея в пределах 5 минут → login.status = pending → трей просто продолжает опрос (безопасно, протокол не меняется). Срок истёк → "expired" → предложить повторить. Перезапуск службы → попытка потеряна (deviceCode на диск не пишем) → трей по своей несекретной отметке «вход начат в T» видит state none и предлагает повторить. Входит в E4-5.
2. pc-token: стирают refresh только явный список: auth.required, pc.not_found, revoked, reuse.detected, pc.key_required. bad.request, неизвестные, временные и прочие известные коды — не стирать (Rejected/Offline). Задание E4-4c.
