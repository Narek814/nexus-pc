# Nexus PC — инструкции для Claude Code

Проект — iPhone-приложение и Windows-агент для управления ПК по домашней сети. Сейчас идёт подготовка к публичному продукту: план в `docs/COMMERCIAL_PLAN.md`.

**Единый источник правил** — `.claude/AGENT_RULES.md`: запреты, роли, зоны записи, проверки, передача задач, технические ограничения. Эти правила обязательны и для главной сессии. Здесь описан только порядок работы главной сессии с субагентами.

## Субагенты (`.claude/agents/`)

| Агент | Тип | Когда вызывать |
|-------|-----|----------------|
| `code-architect` | анализ | структура, протокол, план изменений, затрагивающих несколько компонентов |
| `security-auditor` | анализ | аудит pairing, TLS, ключей, IPC, установщика, сторонних компонентов и их лицензий, аккаунтов |
| `qa-engineer` | анализ (запускает проверки) | прогон тестов, разбор CI, регрессии, тест-планы, приёмка заданий |
| `ios-developer` | запись: `ios/**` | код Swift/SwiftUI, локализация iOS |
| `windows-developer` | запись: `windows/**`, `shared/**` по плану | C#: Agent, Tray, Setup, тесты, локализация Windows |
| `android-developer` | запись: `docs/ANDROID_ROADMAP.md` | совместимость с будущим Android; `android/**` — после одобрения владельца |
| `ui-ux-designer` | запись: `docs/design/**` | экраны, навигация, дизайн-система, тексты EN/RU, доступность |
| `release-manager` | запись: workflow, `tools/`, документы релиза, версии | проверка готовности и подготовка релизов, без публикации |

## Порядок работы главной сессии

1. Задача затрагивает несколько компонентов, протокол или безопасность → сначала `code-architect` (и `security-auditor`). План с изменением протокола, зависимостей, безопасности или удалением функциональности согласуется с владельцем.
2. Исполнителю передаётся блок «Задание» из плана **дословно** (`.claude/AGENT_RULES.md`, раздел 8). Субагент не видит этот разговор.
3. По умолчанию работает **один агент**; несколько одновременно — только с отдельного разрешения владельца. Агенты с правом записи — всегда по одному (охранник отклонит второго). Запускай только нужных агентов и только при реальной пользе; не поручай двум агентам одни и те же файлы; не запускай агента ради подтверждения известного результата.
4. После исполнителя — `qa-engineer` с блоком «Передача в QA». Не принято → новое задание исполнителю.
5. Отчёт с пометкой `НУЖНО РЕШЕНИЕ` выносится владельцу, а не решается за него.
6. Коммиты и push делает только главная сессия, в рабочую ветку. Перед необратимыми действиями охранник запрашивает подтверждение. Не обходить.
7. Apple Developer Program и публикация в App Store — последний этап проекта.
8. Экономия лимита — `.claude/AGENT_RULES.md`, раздел 7а. Перед каждым заданием оцени минимальный объём анализа, разработки и тестирования.
9. Отчёт владельцу — коротко: что сделано; какие файлы изменены; какие тесты запущены и результат; что осталось; нужны ли решения. Без пересказа истории.
10. Для фоновых задач всегда сообщай ожидаемую длительность и время окончания по местному времени владельца (UTC+4).
11. **HybridAI (локальная модель через MCP, только в локальной сессии на ПК владельца).** Подходящую задачу сначала отдавай Researcher, если это действительно экономит лимит Claude: разбор логов CI и тестов, карта файлов и зависимостей перед задачей, полнота и противоречия документации, черновики чек-листов QA и Security, сверка «спецификация ↔ код». Подробно — `.claude/AGENT_RULES.md`, раздел 7б. Если HybridAI недоступен (`health` не отвечает), продолжай работу обычным способом и скажи об этом одной строкой; интеграцию не чини.
