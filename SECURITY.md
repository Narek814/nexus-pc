# Nexus PC — Безопасность

Статус: **v0.1, этап P0** (модель угроз и обязательные требования; реализации пока нет).

## 1. Что защищаем
- Управление ПК (выключение, запуск программ, ввод с клавиатуры/мыши).
- Изображение экрана, содержимое буфера обмена, файлы.
- Ключи сопряжения и токены сессий.
- Историю действий и телеметрию (приватные данные).

## 2. Модель угроз
| Угроза | Пример | Меры |
|--------|--------|------|
| Посторонний в той же Wi-Fi сети | Сканирует порты, пытается отправить команду | Только TLS; без сопряжённого ключа агент отвечает лишь на `hello`/`pair`; rate limit; сопряжение только при подтверждении на ПК. |
| MITM в LAN | Подмена агента | Pinning сертификата агента (отпечаток из QR при сопряжении). |
| Утерянный/украденный iPhone | Доступ к ПК | Ключ в Secure Enclave, доступ по Face ID/коду для `critical`; отзыв устройства на ПК одним кликом. |
| Скомпрометированный Relay | Чтение/подмена трафика | E2E-шифрование поверх relay (Noise/TLS внутри туннеля); relay видит только метаданные. |
| Prompt injection в AI | «Удали System32» | AI выдаёт только шаги из каталога команд; детерминированный валидатор; подтверждение пользователем. |
| Подмена Tray локальным вредоносом | Процесс подключается к pipe | ACL на pipe + проверка пути и подписи процесса-клиента. |
| Path traversal в файлах | `..\..\Windows` | Канонизация пути, запрет reparse points/символических ссылок, только разрешённые корни. |
| Утечка паролей через буфер | Синхронизация скопированного пароля | Только ручная отправка; пропуск форматов, помеченных менеджерами паролей (`ExcludeClipboardContentFromMonitorProcessing`, `CanIncludeInClipboardHistory=0`). |

## 3. Обязательные требования
1. **Шифрование:** TLS 1.2+ (предпочтительно 1.3) для WSS/HTTPS; DTLS-SRTP для WebRTC. Нет нешифрованных режимов, даже «для отладки» в релизной сборке.
2. **Сопряжение:** QR на экране ПК содержит `pcId`, адрес, отпечаток сертификата, одноразовый код (TTL 2 мин). Сопряжение подтверждается кнопкой на ПК.
3. **Аутентификация:** iPhone — ключ P-256 в Secure Enclave; агент — ключ TLS-сертификата в хранилище компьютера Windows (CNG, неэкспортируемый). Вход: challenge-response по каждому соединению (docs/API.md «Вход»); подпись привязана к nonce, `pcId`, `deviceId` и отпечатку TLS-сертификата. Вход живёт ≤ 1 ч на соединении; отдельных токенов нет.
4. **Авторизация:** разрешения на устройство × на ПК (`power`, `apps`, `monitoring`, `input`, `screen`, `files`, `clipboard`, `rgb`, `automation`, `ai`). По умолчанию после сопряжения выдаются только `monitoring`, `apps`, `power` — остальное включается явно.
5. **Нет произвольного выполнения:** нет команд shell/PowerShell/«запустить путь». Приложения — только из реестра, добавленного/подтверждённого на ПК. Закрытие — только приложений из того же реестра.
6. **Критические действия:** shutdown/restart — подтверждение на iPhone (+ Face ID по настройке); удалённый экран и управление вводом — подтверждение **на ПК** при первом подключении и видимый индикатор трансляции с кнопкой «Стоп».
7. **Сеть:** агент слушает только на LAN/VPN-интерфейсах; никаких UPnP и пробросов портов. Удалённо — VPN или Relay с исходящим соединением.
8. **Защита API:** валидация каждого сообщения по JSON Schema, лимиты размеров, rate limiting, защита от повторов (`id` + `ts`, окно ±5 мин).
9. **Секреты на iPhone:** только Keychain (`kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`), общий доступ app/widget через Keychain access group. Никаких ключей AI в бинарнике приложения.
10. **Журнал аудита:** каждая команда (кто, когда, что, результат) пишется в историю на ПК; хранение настраивается.
11. **Внешние пуши (ntfy/Telegram, D11):** в тексте уведомления — только тип события и имя ПК, без путей, имён файлов, содержимого буфера, IP-адресов. Топик ntfy — случайный (≥ 128 бит) и хранится как секрет; при возможности — свой сервер ntfy или токен доступа.
12. **Флаг подтверждения `confirmed`** — защита от случайных действий (UX), а не механизм безопасности: его ставит клиент после подтверждения пользователем. Безопасность обеспечивают ключи и разрешения (п. 3–4). Для удалённого экрана и ввода подтверждение дополнительно требуется на самом ПК.
13. **Обновления:** подписанные сборки Agent/Tray; служба работает с минимально необходимыми правами (решение об учётной записи — P1, см. ниже).

## 4. Решения P1b и открытые вопросы
- **Учётная запись службы — `LocalSystem` (временно).** Нужен доступ к хранилищу сертификатов компьютера и `SeShutdownPrivilege`. Компенсация: строгая проверка всех входящих данных, белый список команд, нет запуска процессов из службы. Переход на виртуальную учётную запись `NT SERVICE\NexusPCAgent` с выдачей только `SeShutdownPrivilege` и ограничение привилегий через `sc.exe privs` — после ручной проверки на реальном ПК (нельзя проверить в облаке).
- **Канал администратора** — именованный канал `NexusPC.Admin`: доступ SYSTEM и повышенным администраторам, сетевой доступ явно запрещён (`NETWORK` deny), `FirstPipeInstance` против перехвата имени. Через него — открытие сопряжения, подтверждение, отзыв устройств, разрешения. Открыто: клиент пока не проверяет, что сервер канала — именно служба (подмена канала до старта службы даёт злоумышленнику только поддельные запросы на подтверждение, но не ключи).
- **Файлы данных** — `C:\ProgramData\NexusPC`, наследование отключено, доступ только SYSTEM и Administrators. Журнал аудита `audit.log` (JSON-строки, без содержимого запросов, ротация 5 МБ).
- **DevClient** хранит закрытый ключ **без шифрования** — только для проверки, не для повседневного использования.
- Формат E2E поверх Relay (Noise IK vs вложенный TLS) — только если когда-либо понадобится Relay (D11).
